## 2025-02-26 - Fix SSRF IPv4-mapped bypass in ipaddress validation
**Vulnerability:** The codebase uses `ipaddress` for SSRF protection and checks if an address `is_link_local` or `is_unspecified`. However, for IPv4-mapped IPv6 addresses (e.g. `::ffff:169.254.169.254`), `is_link_local` on the main object evaluates to `False`. The code only checked if `ipv4_mapped` was `is_link_local`, but missed checking if it was `is_unspecified` or `is_loopback` which could also be used to bypass SSRF protections to local services. Moreover, since `127.0.0.1` should be allowed (as local Ollama is allowed), `::ffff:127.0.0.1` must also be allowed, but `169.254.169.254` and `::ffff:169.254.169.254` must be blocked.
**Learning:** `ipaddress.ip_address` does not inherit standard checks to its IPv4-mapped counterpart. If an IPv6 object maps to IPv4, you must re-run all blocklist checks (`is_link_local`, `is_unspecified`) on the mapped address to prevent bypasses. But for local services (like local Ollama server), loopback should not be blocked.
**Prevention:** When validating IP addresses to block SSRF, check `ip_obj.ipv4_mapped` property and explicitly run all necessary boolean checks (`is_link_local`, `is_unspecified`, etc.) against the mapped object as well.
