## 2025-02-28 - Block SSRF Bypasses via IPv4-Mapped IPv6 Literals
**Vulnerability:** The application was vulnerable to SSRF bypasses via IPv4-mapped IPv6 literals (e.g., `::ffff:127.0.0.1` or `::ffff:169.254.169.254`). While Python's `ipaddress` module parses these addresses, calling properties like `is_loopback` or `is_link_local` on the primary IP object may return `False` or not behave as expected if it's evaluated strictly as IPv6. Furthermore, if the code conditionally checks `ipv4_mapped` but only restricts `is_link_local` on the mapped IP (as seen in `gui/sharpness_tool.py` and `tools/ollama.py`), an attacker could bypass loopback (`is_loopback`) and unspecified (`is_unspecified`) restrictions by wrapping 127.0.0.1 or 0.0.0.0 in an IPv4-mapped IPv6 literal.
**Learning:** `ipaddress.ip_address` correctly identifies that an address is `ipv4_mapped`, but does not automatically proxy security property checks (like `is_loopback`) to the mapped address in all contexts or Python versions. Explicitly checking the mapped address is crucial for comprehensive protection.
**Prevention:** Always verify properties like `is_unspecified`, `is_link_local`, and `is_loopback` on the primary object. Crucially, if the object has an `ipv4_mapped` property, explicitly run all checks on the mapped address as well to prevent bypasses using IPv4-mapped IPv6 literals.
